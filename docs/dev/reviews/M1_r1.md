# 验收卡 M1 · 第 1 轮

## AI 部分

### 怎么跑起来
解压 `claude-multi-launcher-M1.zip` 到任意文件夹（例如 `D:\tools\claude-multi-launcher`），在该文件夹的地址栏输入 `powershell` 回车，然后用下面的命令（`-ExecutionPolicy Bypass` 只对这一条命令生效，不改系统设置）：
`powershell -ExecutionPolicy Bypass -File .\claude-multi.ps1 help`
先跑自测：`powershell -ExecutionPolicy Bypass -File .\tests\Test-Core.ps1`

### 3 分钟体验路线
1. 运行自测 `powershell -NoExit -ExecutionPolicy Bypass -File .\tests\Test-Core.ps1`（`-NoExit` 让窗口不自动关；结果同时保存在 `tests\Test-Core.result.txt`）→ 期望每行 PASS，最后一行 `Failed: 0`。**无论成败都把输出或那个文件的内容贴回来**（这是我这里无法运行的部分）。
2. `claude-multi.ps1 add Study -WhatIf` → 期望出现“【预演】”，列出四个位置：登录数据 `...\AppData\Roaming\Study`、工作区记忆 `...\.claude-study`、专用文件夹 `...\Workspaces\Study`、临时目录，且什么都没创建。
3. 去掉 `-WhatIf` 真正创建 → 期望桌面出现 `Claude (Study)`，你原来的 `Workspaces\Study` 里的文件完好无损。
4. 再 `add Work`，然后 `paths Study` → 期望“独立性检查：通过”。
5. 故意出错：`add Bad -ConfigDir "$env:USERPROFILE\.claude"` → 期望被拒绝，并用中文说明原因，没有创建任何东西。
6. 双击桌面 `Claude (Study)` → 期望打开一个新的 Claude 窗口；在里面登录你的账号（一次只登一个）。
7. 再双击 `Claude (Work)` → 期望另一个独立窗口，登录另一个账号；两个窗口同时存在。

### AI 已验证（你不用再测）
- 5 个 PowerShell 文件括号配对正确、都带 UTF-8 BOM（避免中文乱码）。
- 中英文案各 75 个键，键和占位符完全一致；代码引用的键都存在。
- 代码里没有注册表写入、联网、提权、Invoke-Expression、读取凭据令牌；删除类调用全仓库只有两处（覆盖自己的配置临时文件、删除自己创建的快捷方式）；仓库里没有任何图标或二进制。
- README 有非官方声明、致谢和 MIT 许可证；没有第三方 API 或规避用量限制的功能。

### 请你重点判断（只有人能判断的）
- Q1：中文输出读起来清楚吗？报错是不是说人话？可以用 `lang en` 对比英文。
- Q2：四个默认位置对不对？尤其是工作区记忆 `.claude-study`（小写）和临时目录 `%LOCALAPPDATA%\claude-multi-launcher\tmp\Study`。
- Q3：快捷方式用 `-ExecutionPolicy Bypass`（仅进程级）并隐藏窗口，能接受吗？备选：改成显示窗口，出错更容易看到。
- Q4：独立性规则比设计略严（包含共用位置的目录也拒绝）。有没有你想用却被拒绝的路径？
- Q5：`launch` 每次会打印 4 行说明和提醒，是否太啰嗦？

### 已知不足（别在这里花时间）

- 还没有 doctor、图形界面、带分级确认的数据卸载；`~/Claude/` 目前不隔离，只提示。
- 重复点击同一个 profile 是否聚焦已有窗口，依赖 Claude 自身，不是我们的代码。
